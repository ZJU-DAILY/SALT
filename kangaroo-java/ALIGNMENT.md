## Fast 表项不变量

令当前同组头为 b，查询前导零 k=lead(current XOR b)。对于 k<64，表项保存从组头向旧值方向遇到的第一个“边长不大于 k”的相邻边左端点，并且仅在该边长等于 k 时存在。

追加 b、新旧组头 a 的相邻边长为 ell 时：

1. k<ell：新边不会阻断第一跳，旧表项保留。
2. k=ell：新边就是第一条合格边，左端点 a 成为候选。
3. k>ell：新边比 k 短，阻断进一步寻找，表项失效。
4. ell=64：新旧头完全相同，所有小于64的表项保留。

候选 c 存在时，lead(c XOR b)=k。current 和 c 都在第 k 个前导位之后首次偏离 b，因此二者在该位相同且前 k 位相同，lead(current XOR c)>k。这正是无需额外 XOR 复查的原因。窗口过期时检查逻辑序号；第一个候选已过期意味着更旧的候选也过期。k=64 直接选择组头。

此推导建立了我们这份表维护与第一跳解释的一致性，不是对作者数据结构的断言。正式测试用不依赖该表的线性扫描 oracle 检验10万次查询，含65个尾随零分组、重复组头及窗口淘汰；图7分别选到 Compact 的 h5 和 Fast 的 h11。

## 为什么没有删除 00+index

此前审计把§6.4的一句话列为未对齐疑点。本轮结合上下文作出更谨慎的结论：该段以 Gorilla 为消融基线，不能推断它要求删除图6的任意历史相同值引用分支。连续重复 `a,a` 能被RLE吸收，非连续重复 `a,b,a` 不能；直接删除会另造一种码流。

本轮不添加未经依据的开关，也不把这种猜测作为默认编码。保留图6三分支，对两种重复分别测试。作者最终是否重组标签、如何编码游程长度，仍需作者代码或说明。
